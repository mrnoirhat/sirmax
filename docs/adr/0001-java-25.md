# 0001 — Java 25 LTS como baseline del escritorio y el dominio

- **Estado:** Aceptado
- **Fecha:** 2026-08-27
- **Decisores:** Ingeniería principal SIRMAX
- **Fase relacionada:** 0–1

## Contexto

El master prompt fija Java moderno como tecnología de backend/dominio/aplicación y el escritorio como
plataforma principal (Windows). Necesitamos una versión concreta y de soporte largo (LTS) para el
baseline, con `jpackage` maduro para empaquetar un runtime que el usuario final no tenga que
instalar.

Java 25 es el LTS más reciente (septiembre 2025), con `jpackage` estable, _pattern matching_,
_records_, _sealed types_, _virtual threads_ y `Foreign Function & Memory API` disponibles, todo útil
para un producto de escritorio local-first.

## Decisión

El baseline del código Java (módulos `sirmax-*` de `apps/desktop` y el futuro `backend/`) es
**Java 25 LTS**. `toolchain { languageVersion = JavaLanguageVersion.of(25) }` en Gradle. El
`--release 25` se fija en la compilación. La distribución recomendada para desarrollo y CI es
Eclipse Temurin.

Si aparece una razón fuerte para cambiar de LTS, se registrará en un ADR que supersede a este.

## Consecuencias

**Positivas**
- `jpackage` produce instaladores Windows con runtime embebido (requisito del master prompt).
- Acceso a `records`, `sealed`, _pattern matching_ y `virtual threads` para dominio expresivo y
  trabajo de fondo sin frameworks.
- Ventana de soporte larga.

**Negativas / costes**
- CI y máquinas de desarrollo deben tener JDK 25 (documentado en `DEVELOPMENT.md`).
- Algunas librerías tardías pueden no declarar soporte formal para 25; se mitiga eligiendo
  dependencias con buen historial de compatibilidad.

**A vigilar**
- Fecha de fin de soporte del LTS y aparición del siguiente LTS.

## Alternativas consideradas

- **Java 21 LTS** — sólido y muy soportado, pero es el LTS anterior; preferimos empezar en el más
  reciente dada la vida útil esperada del producto.
- **Java 17 LTS** — demasiado antiguo para un proyecto que arranca en 2026.
- **Kotlin/JVM** — buen lenguaje, pero el master prompt especifica Java y el ecosistema JavaFX +
  jpackage + herramientas de la organización es más directo en Java puro.
